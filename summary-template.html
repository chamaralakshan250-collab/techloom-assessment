CORE DESIGN Concurrency Control & ACID State Engine

Critical Section Serialization Architecture

To achieve mathematically guaranteed zero overselling, both systems avoid naive asynchronous read-then-write updates. Instead, all inventory state modifications are dispatched through an in-memory transactional mutex queue: 

async runInTransaction(callback) {
  const release = await this.mutex.acquire();
  try {
    const snapshot = JSON.parse(JSON.stringify(this.state));
    const result = await callback(this.state);
    await this.persist();
    return result;
  } catch (err) {
    this.state = snapshot; // Full atomic rollback
    throw err;
  } finally {
    release();
  }
}

Formula & Reservation Lifecycle

Inventory maintains three real-time quantities per item:

availableStock = totalStock - reservedStock
State Trigger Event Inventory Impact
RESERVED Checkout started reservedStock += qty
PAID Payment successful totalStock -= qty, reservedStock -= qty
EXPIRED 5-min TTL exceeded reservedStock -= qty (restored)
FAILED Card declined reservedStock -= qty (restored)
REFUNDED Order cancelled totalStock += qty (restocked)
